# after/syntax

## Purpose
This directory is currently empty. It is Neovim's `after-directory` slot for
legacy regex `:syntax` overrides that load after any plugin-provided
`syntax/<filetype>.vim`. Git history (commit `b7c5c93`, "after: cleanup
after/ftplugin and after/syntax", 2023-03-22) shows its contents were
removed together with a large batch of VimScript `ftplugin` cruft, as this
configuration migrated filetype-specific behavior toward Lua ftplugins
(`after/ftplugin/`) and Tree-sitter query overrides (`after/queries/`). It
has stayed empty since; the directory itself is not git-tracked (git does
not track empty directories) and currently exists only on disk.
Do not confuse this with the top-level `syntax/` directory at the repo root
(a *different* directory — `:h syntax` runtimepath entry, not
`after/syntax`), which is still active and holds real `:syntax` files
(`go.vim`, `kitty.vim` generated by `script/gen-kitty-syntax.py`,
`markdown.vim`, `zsh.vim`, etc.) plus two `.lua` syntax modules — see the
repo root `syntax/AGENTS.md` for that directory.

## For AI Agents

### Working In This Directory
- Only add a file here if a filetype needs a `:syntax` override that must
  win over a plugin's own `syntax/<filetype>.vim` and Tree-sitter highlights
  cannot express it (Tree-sitter is this repo's default highlighting path —
  prefer `after/queries/<language>/highlights.scm` first; see
  `after/queries/AGENTS.md`).
- If Neovim's `syntax on`/legacy regex highlighting isn't active for the
  target filetype (this config is Tree-sitter-first), a file placed here
  will not be sourced at all — confirm `:filetype` and whether
  `vim.treesitter.highlighter` is attached to the buffer before debugging
  why a new file here has no effect.
- Do not resurrect content from the pre-2023-03-22 history in `git log
  -- after/syntax` without verifying it is still needed; it was removed
  deliberately as part of the Lua/Tree-sitter migration, not incidentally.

### Testing Requirements
No content, no tests. If a file is ever added, verify manually by opening a
buffer of the target filetype and confirming the expected `:syntax`
highlight group applies (`:Inspect` / legacy `:syntax list <group>`).

### Common Patterns
None — no files exist to establish a pattern. Follow the conventions already
established in `after/ftplugin/` (per-filetype Lua) or `after/queries/`
(Tree-sitter `.scm`) instead unless a genuine `:syntax`-only override is
required.

### External

(`:h after-directory`, `:h syntax`). Effectively superseded by Tree-sitter
